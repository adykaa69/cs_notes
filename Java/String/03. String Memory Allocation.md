# 3. String Memory Allocation
**Where Strings live in memory**, **why the String Pool exists**, and **how this affects comparison using `==` and `equals()`**.
## 3.1 JVM Memory Overview
- From a `String` point of view, we only care about the **heap**.
	- Since **Java 7**, the **String Constant Pool (SCP)** is located **inside the heap**.
- Conceptually:
```
Heap
 ├── String Constant Pool (shared, deduplicated Strings)
 └── Regular heap objects (non-pooled Strings)
```
- Important:
- Stack memory does **not** store String objects  
- Variables only hold **references**
- Objects always live on the heap
## 3.2 String Constant Pool (SCP)
- The **String Constant Pool** is:
	- A JVM-managed cache of `String` objects 
	- Ensures **one unique String instance per value**
	- Shared across the entire JVM
- Rule:
	- If the same String literal already exists in the pool, Java reuses it instead of creating a new object.
	- This is only safe, because `String` is **[[immutable]] #todo**.
